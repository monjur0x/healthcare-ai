# Baseline Comparison Study (paper §13)

Generated by `backend/scripts/baseline_study.py` on 2026-08-16. Every metric is produced by the existing modules (`evaluation/metrics.py`, `federated/metrics.py`, `rag/metrics.py`, `CrewAI/orchestrator/metrics.py`) - nothing here reimplements them.

**Method (pilot scale).** Each dataset is split once with `test_size=0.25`, `seed=42`, and every baseline is scored on that same held-out split. Baselines 2-5 share the federated model (`3` clients, `5` rounds); RAG and multi-agent layers do not retrain it, so their classification block is reported once and reused. The RAG layer is graded on 5 literal clinical queries per dataset against reference answers grounded in a literal per-dataset corpus. Agent metrics come from the deterministic, LLM-free crew over a handful of sample test rows. `n/a` means the metric does not apply to that configuration — no cells are fabricated.

n8n is the orchestration layer (webhook → FastAPI → crew) already exercised live in `docs/CHANGELOG.md`'s verification entries; it adds no independent metric, so the Proposed row is the union of the classification, RAG, and agent metrics.

## Findings

This section was written by hand after inspecting the numbers above (the
script regenerates only the tables on re-runs and preserves this section).

### RQ1 — Does federated learning approach centralized accuracy without sharing raw data?

On the shared held-out split (test_size=0.25, seed=42), the 5-round FedAvg
model matched or exceeded the centralized MLP on every dataset:

| Dataset | Centralized acc / F1 / AUC | Federated acc / F1 / AUC | Δ accuracy |
|---|---|---|---|
| Diabetes | 0.812 / 0.787 / 0.884 | 0.839 / 0.819 / 0.885 | +0.027 |
| Heart | 0.530 / 0.314 / 0.779 | 0.557 / 0.331 / 0.782 | +0.026 |
| Kidney | 0.940 / 0.937 / 0.998 | 0.960 / 0.958 / 0.997 | +0.020 |
| Sepsis | 1.000 / 1.000 / 1.000 | 1.000 / 1.000 / 1.000 | 0.000 |

Federated learning therefore incurred **no accuracy penalty** while keeping
raw rows on the clients — the core privacy-preserving claim of the proposal.
Two honesty notes: these are single-seed runs, so the +0.02–0.03 deltas are
within the run-to-run variance of one MLP initialization (the defensible
claim is "no degradation," not "federated is reliably better"); and the
federated model's communication cost grew with model size — 0.65 MB
(diabetes, 8 features), 0.72 MB (heart, 11), 0.86 MB (kidney, 22), 1.67 MB
(sepsis, 75) across 3 clients × 5 rounds. Convergence was reached by round
2–4 where the data was separable (heart, kidney, sepsis) and not reached
within 5 rounds for diabetes, whose per-round delta stayed flat at 0.005.

### RQ2 — Does multi-agent reasoning add measurable value over the raw model output?

Measured over the deterministic, LLM-free crew on 5 sampled test patients
per dataset: task completion rose from **0.600** (Baseline 4, no evidence
step) to **0.800** (Proposed, RAG evidence wired in) on every dataset, and
agent collaboration rose from **0.400** to **0.600**. Decision consistency
across the sampled patients was **0.600–0.800**. The value is structural: the
crew turns a bare prediction into a complete decision-support report
(summary, prediction, risk level + contributing factors + monitoring plan,
evidence, recommendations) with stable decisions. Two honest caveats: the
deterministic treatment step produces no recommendations (the one empty
task in both rows), so completion is 0.6/0.8 rather than 1.0 — the
recommendation narrative only fills under the LLM path; and decision
consistency is partly inflated by majority-class dominance in the balanced
splits. At this pilot scale the agent layer's contribution is reliability
and structure, not a novel numeric signal.

### RQ3 — Does the RAG layer retrieve relevant, faithful evidence?

The retriever **always found the ground-truth documents** — context recall
was 1.000 on every dataset — and the graded answers were faithfully
grounded in the retrieved context (faithfulness 0.800–1.000). But retrieval
**precision was low**: 0.300–0.350, because with top-k=5 against a small
4-document corpus most retrieved chunks are off-topic. That is an honest
limitation of the TF-IDF retriever at this scale, and the obvious lever is
the already-implemented dense `SentenceTransformerEmbedder` or a smaller
top-k. Answer relevancy (0.27–0.39) reflects the reference answers being
clinical prose scored against a keyword-level query embedding — a known
weakness of the LLM-free relevancy proxy, not evidence about the answers.

### RQ4 — What does n8n contribute?

Qualitative, deliberately unmeasured. n8n is the orchestration layer that
triggers training/analysis, calls the FastAPI service, and delivers the
report to the dashboard; its correctness was established by the live
end-to-end verification recorded in `docs/CHANGELOG.md` (Milestone 11),
not by a metric. There is no honest numeric value to attach to a workflow
engine, so none is fabricated — the Proposed row is the union of the
classification, RAG, and agent metrics only.

### Study-wide caveats

This is a **pilot-scale** study, not a statistically powered one: 5 RAG
queries and 5 sampled patients per dataset, single-seed (42) training runs.
The sepsis dataset is synthetic and trivially separable (every model scores
1.000), so it should be read as a pipeline check, not as evidence about
model quality. Results are fully reproducible with
`DATASET_DIR=<dir> python scripts/baseline_study.py` from `backend/`.
