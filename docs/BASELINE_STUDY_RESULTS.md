# Baseline Comparison Study (paper §13)

Generated by `backend/scripts/baseline_study.py` on 2026-09-11. Every metric is produced by the existing modules (`evaluation/metrics.py`, `federated/metrics.py`, `rag/metrics.py`, `CrewAI/orchestrator/metrics.py`) - nothing here reimplements them.

**Method.** Each dataset is split once per seed with `test_size=0.25`, `seeds=[42, 43, 44, 45, 46]`, and every baseline is scored on that seed's held-out split; every table cell is the mean ± sample SD across the 5 seeds (a zero SD renders as a plain number). Baselines 2-5 share the federated model (`3` clients, `5` rounds); RAG and multi-agent layers do not retrain it, so their classification block is reported once and reused. The RAG layer is graded on 5 literal clinical queries per dataset against reference answers grounded in a literal per-dataset corpus. Agent metrics come from the deterministic, LLM-free crew over a handful of sample test rows. `n/a` means the metric does not apply to that configuration — no cells are fabricated.

n8n is the orchestration layer (webhook → FastAPI → crew) already exercised live in `docs/CHANGELOG.md`'s verification entries; it adds no independent metric, so the Proposed row is the union of the classification, RAG, and agent metrics.

## Findings

This section was written by hand after inspecting the numbers above (the
script regenerates only the tables on re-runs and preserves this section).

### RQ1 — Does federated learning approach centralized accuracy without sharing raw data?

Across 5 repeated splits (test_size=0.25, seeds 42–46), the 5-round FedAvg
model matched the centralized MLP on every dataset — every centralized-vs-
federated gap is smaller than one sample SD:

| Dataset | Centralized acc / F1 / AUC | Federated acc / F1 / AUC | Δ accuracy |
|---|---|---|---|
| Diabetes | 0.848 ± 0.021 / 0.831 ± 0.026 / 0.903 ± 0.014 | 0.854 ± 0.022 / 0.838 ± 0.027 / 0.905 ± 0.023 | +0.006 |
| Heart | 0.789 ± 0.025 / 0.787 ± 0.024 / 0.866 ± 0.035 | 0.784 ± 0.029 / 0.782 ± 0.029 / 0.876 ± 0.034 | −0.005 |
| Kidney | 0.988 ± 0.008 / 0.987 ± 0.009 / 1.000 | 0.992 ± 0.011 / 0.991 ± 0.012 / 1.000 | +0.004 |
| Sepsis | 1.000 / 1.000 / 1.000 | 1.000 / 0.999 ± 0.001 / 1.000 | 0.000 |

Federated learning therefore incurred **no accuracy penalty** while keeping
each client's training rows local — the core privacy-preserving claim of the proposal.
(Note the old single-seed table showed diabetes +0.027; across seeds that
shrinks to +0.006 ± ~0.02 — exactly the kind of single-split luck the
multi-seed design guards against.) Two honesty notes: the federated accuracy
numbers are scored on a server-held central hold-out slice
(`data/hospitals/central_holdout.csv`), so the evaluation itself sees raw
rows even though training never moves them (client-side hold-out evaluation
is future work); and the federated model's communication cost grew with
model size — 0.62 MB (diabetes, 8 features), 0.69 MB (heart, 13), 0.82 MB
(kidney, 22), 1.60 MB (sepsis, 75) across 3 clients × 5 rounds.
Convergence averaged round 2–3 where the data was separable (heart 2 ± 0,
kidney 2 ± 1, sepsis 2); diabetes converged at 3 ± 2, i.e. the round itself
varies seed to seed on the hardest dataset.

### RQ2 — Does multi-agent reasoning add measurable value over the raw model output?

Measured over the deterministic, LLM-free crew on 5 sampled test patients
per dataset per seed: task completion rose from **0.800** (Baseline 4, no
evidence step) to **1.000** (Proposed, RAG evidence wired in) on every
dataset with zero seed variance, and agent collaboration rose from **0.600**
to **0.800**, also stable. Decision consistency across the sampled patients
varied honestly by dataset and seed — 0.640 ± 0.089 (diabetes, heart),
0.760 ± 0.167 (kidney), 0.880 ± 0.110 (sepsis). The value is structural: the
crew turns a bare prediction into a complete decision-support report
(summary, prediction, risk level + contributing factors + monitoring plan,
evidence, recommendations) with stable decisions. The evidence-retrieval
section is the discriminator: disabling the RAG pipeline leaves that section
empty, which lowers the no-RAG completion below the with-RAG run. At this
pilot scale the agent layer's contribution is reliability and structure, not
a novel numeric signal.

### RQ3 — Does the RAG layer retrieve relevant, faithful evidence?

The retriever **always found the ground-truth documents** — context recall
was 1.000 on every dataset — and the graded reference answers were faithfully
grounded in the retrieved context (faithfulness 1.000 across all queries).
But retrieval **precision was low**: 0.300–0.350, because with top-k=5 against
a small per-dataset corpus most retrieved chunks are off-topic. That is an
honest limitation of the TF-IDF retriever at this scale, and the obvious
lever is the already-implemented dense `SentenceTransformerEmbedder` or a
smaller top-k. Answer relevancy (0.28–0.39 across seeds and datasets) reflects the reference answers
being clinical prose scored against a keyword-level query embedding — a known
weakness of the LLM-free relevancy proxy, not evidence about the answers.

### RQ4 — What does n8n contribute?

Qualitative, deliberately unmeasured. n8n is the orchestration layer that
triggers training/analysis, calls the FastAPI service, and delivers the
report to the dashboard; its correctness was established by the live
end-to-end verification recorded in `docs/CHANGELOG.md` (Milestone 11),
not by a metric. There is no honest numeric value to attach to a workflow
engine, so none is fabricated — the Proposed row is the union of the
classification, RAG, and agent metrics only.

### Study-wide caveats

This is a **pilot-scale** study: 5 RAG queries and 5 sampled patients per
dataset, but every training number is now mean ± SD across 5 repeated-split
seeds (42–46) rather than a single split.
The sepsis dataset is synthetic and trivially separable (every model scores
1.000), so it should be read as a pipeline check, not as evidence about
model quality. The kidney dataset has string labels (`ckd` / `notckd`); the
study's own split reproduces the disease-positive orientation exactly as the
training path does, so the reported numbers are directly comparable.
Results are fully reproducible with
`DATASET_DIR=<dir> python scripts/baseline_study.py` from `backend/`.
